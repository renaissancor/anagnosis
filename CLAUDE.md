# Anagnosis — Project Primer

Anagnosis is a CSV-first historical-political dataset. **Schema is two-tier:**

- **Civilization** (top tier; was `state` until the 2026-05-01 rename — still mid-migration in the working tree)
- **Polity** (entity tier; a political entity at the intersection of ethnicity × territory × ideology × time)

**Dynasty** (~192 records) is a **cross-cutting tag** via the `polity_dynasty` junction, *not* a third tier. The earlier "Regime" tier was **dropped** on 2026-05-01 — identity drift inside long-running entities (Roman Republic → Pagan Empire → Christian Empire → Byzantine) is handled by polity-splits at major transitions, not sub-polity periods.

Auxiliary entities: `ethnicity`, `language`, `religion`, `territory`, `figure`, `government`, plus planned `city` (see `docs/model/city.md`).

## CSV-first architecture — sources of truth

**`csvs/*.csv` are the only sources of truth.** Everything under `data/` is generated and must not be hand-edited.

| Source of truth | What it holds |
|---|---|
| `csvs/*.csv` | Entities (civilization, polity, dynasty, figure, government, …) and relations (`polity_dynasty`, `polity_succession`, `polity_territory`, …) |
| `csvs/{language,ethnicity,religion}.csv` | Taxonomies — hierarchy is expressed by the `parent_id` self-reference column (NOT by filesystem path) |
| `csvs/territory.csv` | Territories, grouped via `polity_territory.csv` |

**Generated outputs (do not hand-edit):**

- `data/<entity>/` taxonomy trees (`data/language/`, `data/ethnicity/`, `data/religion/`, singular) — generated by `code/makejson/{languages,ethnicities,religions}.js` from the CSVs. The generator emits the directory nesting; `data/index.js` re-derives each node's `parent` from the **path**, so the on-disk tree shape must match the `parent_id` graph.
- `data/<entity>/*.json` per-entity files — generated by `code/makejson/*.js`
- `anagnosis.db` (DuckDB) — loaded via `scripts/load_csvs.sql` for analytical queries

**The four rules that fall out:**

1. **Edit only sources, never generated JSON.** Changes to entities (including taxonomy hierarchy) go in `csvs/*.csv`; regeneration produces the JSON tree. If you find yourself editing anything under `data/`, stop and find the CSV.
2. **Every CSV must have a logical description** in `docs/model/<concept>.md` — purpose, columns, semantics, FK relationships. A CSV without a model doc is an incomplete commit.
3. **Every CSV must have a generator.** A CSV that no `code/makejson/*.js` consumes is dead data.
4. **Workflow:** edit a CSV row → run the generator → project state updates. Reviews are CSV diffs; JSON diffs are generated noise.

## The pipeline (default loop — memorize this)

**Canonical record: `docs/PIPELINE.md`.** The default after ANY CSV edit:

```bash
npm run make:all   # csvs/*.csv → data/**/*.json via code/makejson/*.js
npm test           # scripts/validate.js — FK integrity; red = broken build
```

`data/` is untracked; a fresh clone regenerates it (`prestart`/`pretest` run `make:all`). Scripts under `scripts/` other than `validate.js` are one-shot curation tools, **not** part of the pipeline — never run them as build steps.

> **Note (2026-06-18):** the three taxonomies are now CSV-sourced. `docs/tree/{language,ethnicity,religion}.md` are **no longer wired into generation** — they are human-readable reference only and may lag the CSVs. The dead scripts `scripts/json_to_csv.js` and `scripts/rebuild-languages.js` were deleted (2026-08-21). There are **no** source-of-truth filesystem trees; the earlier `data/{languages,religions,territories}/` (plural) FS-tree model was never implemented.

## Conventions

- **IDs:** snake_case, stable, never reused
- **Years:** integer; BCE is negative (`-753` = 753 BCE); empty `end` field = ongoing
- **Free-text in CSVs:** avoid commas inside fields — use semicolons or em-dashes
- **Foreign keys:** plain id strings (e.g., `polity.civilization_id` → `civilization.id`)
- **Word "regime"** is acceptable only in: brand mentions (`anagnosis`, `Anagnosis`), English-noun prose ("Pol Pot regime"), and historical reports/snapshots. **Never as an entity term in new code or schema.**

## Schema discipline — FK-driven scoping

Entity tables earn rows by inbound foreign keys, not historical fame. A row belongs in `city`, `figure`, etc. only when something else in the dataset points to it. No decorative reference rows. When seeding, walk the *references* first and back-fill entities. Canonical statement: `docs/model/city.md` *Scope Discipline*.

## Migration status

The `state` → `civilization` rename is **committed** (see `d9f10da`, 2026). Any remaining `state_id` / `state.csv` / `states.csv` references in docs or scripts are stale leftovers to be cleaned up on sight, not design conflicts.

## What this project is *not*

Anagnosis is an **architecture for curation**, not a complete dataset. Coverage is uneven; sparse panels are expected. Decisions are driven by political-history queries, not by exhaustive cataloging.
